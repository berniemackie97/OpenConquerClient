# STARTUP-001Y: 5517 login credential editing

Completes text editing in the account and password fields. Enter and login networking stay disabled, signed realm selection is still required, the protocol is unchanged, and drawing still uses the existing Silk.NET/OpenGL renderer.

## Behavior

- `LoginCredentialInput` holds a fixed-capacity character buffer for each field, the caret position, the selection anchor, pointer-drag capture, focus and revision tracking. Editing is limited to the ASCII characters that were already accepted (`A-Z`, `a-z`, `0-9`, `.`, `-`, `@`, `>`, `_`), with at most 32 characters per field. This limit is for compatibility. It makes no claim about whether retail 5517 accepted other Unicode or IME input. Invalid characters, multi-line pastes and oversized pastes are rejected as a whole, leaving the field unchanged. Text storage has a fixed size, and clipboard text is never used to form file names or URLs.
- Left/Right, Home/End, Shift selection, Ctrl/Cmd+A, Backspace, forward Delete, insertion and replacing a selection all have unit tests. Tab, and Enter in the account field, move focus. Enter never submits a login. Password buffers are zeroed when the context is invalidated, when the window loses focus, on a click outside the fields, and on disposal. `CryptographicOperations.ZeroMemory` clears this particular managed array, but it cannot remove copies the runtime may have made elsewhere.
- `DesktopWindow` provides clipboard access on the event thread through the existing Silk.NET keyboard. Ctrl/Cmd+C and Ctrl/Cmd+X work only on a selection in the account field, and they change nothing until the write to the OS clipboard has succeeded. Copy and cut are disabled in the password field. Pasting into it is still allowed, with the same validation. Clipboard contents come from outside the client and are untrusted. They are never logged or stored in settings. Reading the OS clipboard may allocate memory before validation, but the text is length-checked before it is copied into a credential buffer.
- `LoginCredentialPresentation` measures the font's actual glyph advances to place the caret on click and drag. It scrolls the text whole glyphs at a time within the narrow retail text area, draws a translucent selection behind the text, and blinks the caret using a monotonic clock. Text is not rebuilt every frame. Pointer positions go through the existing framebuffer-to-logical viewport mapping, so HiDPI and window scaling are still handled in one place. The selection color and blink rate are our own choices. The original SWF's colors and timing have not been confirmed. Right-to-left text, grapheme handling, accessibility and IME composition are not supported while the credential alphabet is ASCII only.
- `ClientApplication` plays the existing `key_1/2/3` sounds when an edit actually changes the text. Caret movement, invalid input, a deletion that removes nothing, a failed paste and selection-only changes are silent. The available 5517 `flashLogin.ini` maps `keyboardDown_0..2` to those files. Whether the original SWF plays them on Backspace and Delete has not been confirmed. Playing the same sound sequence for successful deletions as for typed text is this client's own documented choice. Each event plays at most one sound.

## Verification

1. Run a locked restore, `dotnet format --verify-no-changes`, a Release build, the focused client tests, all solution tests, the content-set verification and `git diff --check`, followed by Windows and macOS CI and the publishing checks.
2. With a signed local realm (and no login submission), test in 1024x768 and 800x600 windows: clicking between letters, dragging in both directions, Shift+Arrow, select all, insertion, deletion and replacement, repeated Backspace, Tab, password masking, scrolling at 32 characters, the clipboard restrictions, focus loss, and releasing the pointer outside the panel.
3. Confirm that the password is never drawn or logged in plain text, that no credentials survive a server or catalog change, that the retail cursor and audio still work, that pointer placement is accurate on high-DPI displays, and that scrolled text does not bleed past its scissor rectangle onto the retail panel. Sound must play only when an edit succeeds.
4. OpenAL playback and the original assets are unchanged from STARTUP-001X. A rights and licensing plan approved for release is needed before retail artwork or audio is redistributed commercially.

### Remaining retail investigation

Neither `flashLogin.ini` nor the retail client's native `CMD_SOFTKEYDOWN` bridge shows the Flash/AVM event path for Backspace and Delete, or the SWF's text-selection highlight color and caret blink timing. These only need research if matching retail behavior becomes a requirement. Until then the documented choices above apply. The accepted credential characters are unchanged, IME is not implemented, and there is no network submit command.
