## Input

Input reaches the screen in the retail order: an open dialog, the account list, the buttons, the
credential fields, then the region and server tiles.

- Regions and servers are selected on press (`hitMC.onPress`). Pressing the selected region does
  nothing. Empty holders (`unopenedR`, `unopenedS`) have no hit area.
- Page buttons appear only when there is more than one page. A page turns on release over the
  button that was pressed. Turning a page keeps the selected region and its servers.
- The first signed catalog applies the retail (0, 0) startup selection (`GroupRecord=0`,
  `ServerRecord=0`).
- Credential fields start without focus. Tab moves from the account field to the password field
  and selects the password. Tab in the password field does nothing. The password limit is 15
  (`maxLength` of field 364). Paste works in both fields. Copy and cut work only in the account
  field.
- Regions and servers cannot be navigated with the keyboard. The retail client's native bridge
  polls only Esc, Tab and Enter.

## Server status lights

Sprite 179 `light` (sprite 34, with frames red, yellow, green and purple) sits at (9.3, 62.25) on
every present server. It is drawn above the picture and rollover highlight (depths 1 and 4) and
below the rollover and selection effects (depth 8). An empty slot hides it. `flushLight` shows
frame `state` for states 1 to 4, and frame 4 otherwise.

The retail client sets state 3 on its first `SERVER` push. It then fetches
`ini/common.ini [ServerStatus] URL` (lines of `name status`) once on a background thread and pushes
again with `ServerListEntry_ResolveFlashStatusCode` (0x5EA5A2), which returns 0 for any server the
fetch did not list. A failed fetch is caught inside the loader (0x5EA7C5), so the second push still
happens, with every server at 0. The retail capture was taken with the client firewalled from that
URL (`account.conqueronline.com/status.php`) and shows frame 4 on every server. With no URL, the
loader returns at once and the second push follows the first immediately. This client has no
status URL and draws frame 4 from the start.

## Account history

`CMD_RECORDACCOUNT` happens only through Save and then Ok. `CMD_CLEARACCOUNT` happens only through
Clear and then Ok, and only for an account that is in the history. Cancel changes nothing. The
history holds up to ten account names (UTF-8 JSON, 4 KiB maximum), never passwords, and is written
atomically to a private file. A corrupt or unsupported file is left untouched and disables saving
for the session. Choosing an account from the list replaces the account and clears the password.

## Differences from retail

- Enter does not submit credentials, and no account-server packet is sent.
- Register, Purchase and Help do not open the publisher-era URLs.
- There is no status fetch. The signed catalog identifies realms and their account endpoints, but
  says nothing about whether they are up. A live status would need a separately signed,
  short-lived feed tied to the current catalog.
- Region captions come from the signed catalog. The retail region movies have their own titles
  built in.
- Replacing the catalog clears the password.
