## Input

Input reaches the screen in the retail order: an open dialog, the account list, the buttons, the credential
fields, then the region and server tiles.

- Regions and servers select on press (`hitMC.onPress`). Pressing the selected region does nothing. Empty
  holders (`unopenedR`, `unopenedS`) have no hit area.
- Page buttons appear only with more than one page and turn the page on release over the pressed button.
  Turning a page keeps the selected region and its servers.
- The first authenticated catalog applies the retail (0, 0) startup selection (`GroupRecord=0`,
  `ServerRecord=0`).
- Credential fields: no initial focus; Tab moves account → password and selects the password; Tab in the
  password field does nothing. Password limit 15 (`maxLength` of field 364). Paste works in both fields; copy and
  cut only in the account field.
- No keyboard navigation of regions or servers: the native bridge polls only Esc, Tab and Enter.

## Server status lights

Sprite 179 `light` (sprite 34, frames red, yellow, green, purple) sits at (9.3, 62.25) on every present server,
above the picture and rollover highlight (depths 1 and 4) and below the rollover and selection effects (depth 8);
an empty slot hides it. `flushLight` shows frame
`state` for states 1–4 and frame 4 otherwise.

The retail client seeds state 3 on its first `SERVER` push, then fetches `ini/common.ini [ServerStatus] URL`
(lines of `name status`) once on a background thread and pushes again with
`ServerListEntry_ResolveFlashStatusCode` (0x5EA5A2), which returns 0 for a server the fetch did not list. A
failed fetch is caught inside the loader (0x5EA7C5), so the second push still happens with every server at 0.
The retail capture was taken with the client firewalled from that URL (`account.conqueronline.com/status.php`)
and shows frame 4 on every server. With no URL the loader returns at once and the second push follows the first immediately; the client
has no status URL and draws frame 4 from the start.

## Account history

`CMD_RECORDACCOUNT` happens only through Save → Ok; `CMD_CLEARACCOUNT` only through Clear → Ok, and only for
an account in the history. Cancel changes nothing. The history holds up to ten account names (UTF-8 JSON,
4 KiB maximum), never passwords, written atomically to a private file. A corrupt or unsupported file is left
untouched and disables saving for the session. Choosing an account from the list replaces the account and
clears the password.

## Deliberate differences

- Enter does not submit credentials; no account-server packet is sent.
- Register, Purchase and Help do not open the publisher-era URLs.
- No status fetch. A live status needs a separately signed, short-lived feed bound to the current catalog; the
  signed catalog identifies realms and their account endpoints, not whether they are up.
- Region captions come from the signed catalog; the retail region movies bake their own titles.
- Replacing the catalog clears the password.
