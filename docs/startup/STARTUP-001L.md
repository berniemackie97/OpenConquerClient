# STARTUP-001L — Verified standard 5517 account request framing

## Evidence and scope

The historical native evidence in `20_notes/Network/13_connection_lifecycle.md` and `20_notes/Server/login-credential-envelope.md` establishes ordinary startup type 1060 as a 276-byte little-endian AccountServer message. The standard (not `AccountSetup/Type == 1` OEM) branch encrypts exactly the first 32 bytes of the 128-byte credential field and leaves the trailing 96 bytes zero. Native `CMsg1060__Create` uses fixed-byte-width `strncpy` for the account and protocol server name, and a fixed 128-byte `memcpy` for encrypted credential data. Embedded binary zeroes in the encrypted region are meaningful ciphertext bytes and must not terminate copying.

This slice implements **only** deterministic serialization of that proven plaintext packet envelope. It is intentionally not wired to the login UI, sockets, or session lifecycle. The caller must provide ciphertext that was already generated by the verified 5517 account credential pipeline. Supplying arbitrary bytes, even though technically allowed by this serializer, does not constitute a valid native authentication request.

## Envelope

| Byte offset | Byte count | Data |
| --- | ---: | --- |
| `0` | 2 | Little-endian length: `276` |
| `2` | 2 | Little-endian packet type: `1060` |
| `4` | 128 | Caller-supplied ANSI account bytes, zero padded |
| `132` | 32 | Already-encrypted RC5 standard credential ciphertext, verbatim |
| `164` | 96 | Zero bytes reserved for the remainder of the 128-byte credential field |
| `260` | 16 | Caller-supplied protocol server name bytes, zero padded |

`StandardAccountRequest1060.Write` requires an exactly sized 276-byte destination, a nonempty account no longer than 128 bytes, a nonempty protocol name no longer than 16 bytes, and an exactly 32-byte encrypted credential block. Identity bytes must not contain NUL or ASCII controls; bytes at or above `0x80` are preserved to support future explicit native ANSI encoding policy. The serializer takes **bytes**, not Unicode names, because native field lengths are byte lengths. No implicit UTF-8, CP936, truncation, or replacement encoding is permitted. Names of exactly 128 and 16 bytes, respectively, are represented without an extra NUL terminator, following the documented fixed-width native producer.

The destination is unchanged on validation failures. After successful validation, source spans are snapshotted to bounded stack storage before clearing the destination, so even overlapping source/output buffers produce deterministic frames. The temporary 32-byte ciphertext snapshot is explicitly zeroed before return. Serialization performs no managed allocation on the normal path and has no network or side effects. The complete output frame remains caller-owned sensitive binary data and **must be erased by its future transport owner when no longer required**.

## Trust and authentication boundaries

No production path calls this serializer in this slice. The signed catalog still owns authoritative account ingress; its display label cannot become a routing identity. Future integration must reject any signed `protocolServerName` that cannot be encoded faithfully within the 16-byte native field; no clipping of signed identities is permitted. The native-per-account keypad permutation, per-login-seed RC5 key derivation, standard 32-byte credential encryption, AccountServer connection handshake, encrypted transport, and server response parsing are required separate audited components before any login packet can be transmitted.

In particular, **never** send this plaintext packet directly on a socket. The 5517 connection notes distinguish the handshake cipher from post-handshake encrypted packet transport and require proof of the active AccountServer session state before forwarding a request. This class neither certifies a crypto context nor creates one.

There is no account-login event, socket, credential buffer read, status icon, fabricated endpoint, new retail content, or permission for world entry in this slice. The `OpenConquer.Networking` project is the protocol ownership boundary, and its internal test visibility is limited to `OpenConquer.Client.Tests`.
